Docker Compose gives you a reproducible, single-command local environment that mirrors the shape of production without requiring any cloud account. All four services — the MySQL 8 database, the Spring Boot API, the Node-based Gemini chatbot, and the Vite/nginx React frontend — share a single `examport-network` bridge, so inter-service DNS resolution works exactly as it does in ECS service discovery. Use this setup for day-to-day development, integration testing, or stakeholder demos.

<Note>
  Docker Compose is intended for local development and demos **only**. The database password, JWT secret, and API keys are read from a `.env` file that you must never commit. For production, use the [AWS ECS Fargate deployment](/deployment/aws) backed by Secrets Manager.
</Note>

## Service overview

| Service | Image / Build | Host port | Key dependency |
|---|---|---|---|
| `mysql` | `mysql:8.0` | `3306` | — (healthcheck guards dependants) |
| `backend` | `./backend/Dockerfile` | `8080` | `mysql` (condition: `service_healthy`) |
| `chatbot` | `./chatbot/Dockerfile` | `5000` | — |
| `frontend` | `./frontend/Dockerfile` | `3000` | `backend`, `chatbot` |

Two named volumes persist data between restarts:

| Volume | Purpose |
|---|---|
| `mysql-data` | MySQL data directory — survives `docker compose down` |
| `backend-logs` | Mounted at `/app/logs` inside the API container |

## docker-compose.yml (annotated)

The compose file at the repository root defines every service, its build context, environment variables, port bindings, health check, and network membership. The sections below are pulled directly from the file.

```yaml
version: '3.8'

services:
  # MySQL Database
  mysql:
    image: mysql:8.0
    container_name: examport-mysql
    environment:
      MYSQL_ROOT_PASSWORD: ${DB_PASSWORD:-root}
      MYSQL_DATABASE: examwizards
      MYSQL_USER: examport
      MYSQL_PASSWORD: examport123
    ports:
      - "3306:3306"
    volumes:
      - mysql-data:/var/lib/mysql
    networks:
      - examport-network
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5

  # Backend Service
  backend:
    build:
      context: ./backend
      dockerfile: Dockerfile
    container_name: examport-backend
    environment:
      DB_URL: jdbc:mysql://mysql:3306/examwizards
      DB_USERNAME: examport
      DB_PASSWORD: examport123
      JWT_SECRET: ${JWT_SECRET:-your-jwt-secret-key-here}
      FRONTEND_URL: http://localhost:3000
      GENAI_API_KEY: ${GENAI_API_KEY}
      RAZORPAY_KEY_ID: ${RAZORPAY_KEY_ID}
      RAZORPAY_KEY_SECRET: ${RAZORPAY_KEY_SECRET}
      EMAIL_USERNAME: ${EMAIL_USERNAME}
      EMAIL_PASSWORD: ${EMAIL_PASSWORD}
      EMAIL_FROM: ${EMAIL_FROM}
      EMAIL_ENABLED: ${EMAIL_ENABLED:-true}
      EMAIL_ADMIN: ${EMAIL_ADMIN}
    ports:
      - "8080:8080"
    depends_on:
      mysql:
        condition: service_healthy
    networks:
      - examport-network
    volumes:
      - backend-logs:/app/logs

  # Chatbot (Gemini) — REST /api/ask, health GET /health
  chatbot:
    build:
      context: ./chatbot
      dockerfile: Dockerfile
    container_name: examport-chatbot
    environment:
      GENAI_API_KEY: ${GENAI_API_KEY}
      PORT: 5000
    ports:
      - "5000:5000"
    networks:
      - examport-network

  # Frontend Service
  frontend:
    build:
      context: ./frontend
      dockerfile: Dockerfile
      args:
        VITE_API_BASE_URL: http://localhost:8080/api
        VITE_CHATBOT_API_URL: http://localhost:5000
    container_name: examport-frontend
    ports:
      - "3000:3000"
    depends_on:
      - backend
      - chatbot
    networks:
      - examport-network

networks:
  examport-network:
    driver: bridge

volumes:
  mysql-data:
  backend-logs:
```

<Info>
  The `frontend` build stage embeds `VITE_API_BASE_URL` and `VITE_CHATBOT_API_URL` at compile time via Vite's `ARG`/`ENV` mechanism in the Dockerfile. If you need to point the SPA at a different backend (e.g., a remote dev API), pass the build args explicitly: `docker compose build --build-arg VITE_API_BASE_URL=https://dev.example.com/api frontend`.
</Info>

## Starting the stack

<Steps>
  <Step title="Copy and edit the environment file">
    ```bash
    cp .env.example .env
    # Open .env and set JWT_SECRET, GENAI_API_KEY, RAZORPAY_*, and EMAIL_* values
    ```

    At minimum, `GENAI_API_KEY` must be a real Google Gemini key for the chatbot service to start correctly. The other variables have defaults that work for local testing.
  </Step>

  <Step title="Build images and start all services">
    ```bash
    docker compose up -d
    ```

    On the first run, Docker builds all three custom images (backend, chatbot, frontend) from their respective Dockerfiles before starting. Subsequent starts reuse cached layers and are much faster.
  </Step>

  <Step title="Verify the API health endpoint">
    ```bash
    curl http://localhost:8080/api/auth/health
    ```

    The backend container's own health check uses this same endpoint (see the ECS task definition for the equivalent `CMD-SHELL` probe). A `200 OK` confirms Spring Boot started and connected to MySQL.
  </Step>

  <Step title="Open the frontend">
    Navigate to `http://localhost:3000` in your browser. The React SPA is served by nginx inside the `frontend` container.
  </Step>
</Steps>

## Common operations

<Tabs>
  <Tab title="Logs">
    Follow live logs from the API container:

    ```bash
    docker compose logs -f backend
    ```

    Follow all services simultaneously:

    ```bash
    docker compose logs -f
    ```
  </Tab>
  <Tab title="Rebuild a service">
    Rebuild and restart a single service without affecting the others:

    ```bash
    docker compose up -d --build backend
    ```

    Useful after editing Java source or changing the backend Dockerfile. Replace `backend` with `frontend` or `chatbot` as needed.
  </Tab>
  <Tab title="Stop the stack">
    Stop containers but **keep named volumes** (MySQL data is preserved):

    ```bash
    docker compose down
    ```

    Stop containers **and delete named volumes** (wipes the database — useful for a clean-slate test run):

    ```bash
    docker compose down -v
    ```
  </Tab>
  <Tab title="Exec into a container">
    Open a shell inside the running backend container:

    ```bash
    docker compose exec backend sh
    ```

    Inspect the MySQL database directly:

    ```bash
    docker compose exec mysql mysql -u examport -pexamport123 examwizards
    ```
  </Tab>
</Tabs>

## Dockerfile reference

Each service uses a multi-stage build to keep the final image lean.

<Accordion title="backend/Dockerfile — Maven build → eclipse-temurin:17-jre-alpine">
  The backend uses a two-stage build: Maven 3.9.6 with Eclipse Temurin 17 compiles and packages the jar (`mvn clean package -DskipTests`), then the runtime stage copies only the jar into a minimal `eclipse-temurin:17-jre-alpine` image. The `SPRING_PROFILES_ACTIVE` environment variable defaults to `prod` and can be overridden at runtime.

  ```dockerfile
  FROM maven:3.9.6-eclipse-temurin-17 AS build
  WORKDIR /app
  COPY pom.xml .
  RUN mvn dependency:go-offline -B
  COPY src ./src
  RUN mvn clean package -DskipTests

  FROM eclipse-temurin:17-jre-alpine
  WORKDIR /app
  COPY --from=build /app/target/*.jar app.jar
  RUN mkdir -p /app/logs
  EXPOSE 8080
  ENTRYPOINT ["java", "-jar", "app.jar"]
  ```
</Accordion>

<Accordion title="frontend/Dockerfile — Vite build → nginx:alpine">
  The frontend builds with Node 20 (`npm ci` + `npm run build`) then copies the `dist/` output into an `nginx:alpine` image. The `VITE_API_BASE_URL` and `VITE_CHATBOT_API_URL` build args are baked in at compile time by Vite; they cannot be changed at container runtime without rebuilding.

  ```dockerfile
  FROM node:20-alpine AS build
  WORKDIR /app
  COPY package*.json ./
  RUN npm ci
  COPY . .
  ARG VITE_API_BASE_URL=http://localhost:8080/api
  ARG VITE_CHATBOT_API_URL=http://localhost:5000
  ENV VITE_API_BASE_URL=$VITE_API_BASE_URL
  ENV VITE_CHATBOT_API_URL=$VITE_CHATBOT_API_URL
  RUN npm run build

  FROM nginx:alpine
  COPY --from=build /app/dist /usr/share/nginx/html
  COPY nginx.conf /etc/nginx/conf.d/default.conf
  EXPOSE 3000
  CMD ["nginx", "-g", "daemon off;"]
  ```
</Accordion>

<Accordion title="chatbot/Dockerfile — Node 20 production server">
  The chatbot service is a lightweight Node 20 Alpine image. Only production dependencies are installed (`npm ci --omit=dev`), then `server.js` is copied and started directly.

  ```dockerfile
  FROM node:20-alpine
  WORKDIR /app
  COPY package*.json ./
  RUN npm ci --omit=dev
  COPY server.js ./
  ENV NODE_ENV=production
  EXPOSE 5000
  CMD ["node", "server.js"]
  ```
</Accordion>
